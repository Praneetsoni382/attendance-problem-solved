# PART 2 — PRODUCT PURPOSE

AttendWise is a student-only personal attendance management application.

Its purpose is to let a student:

1. Maintain a personal record of attendance for each scheduled class.
2. Define a weekly timetable from Monday through Saturday.
3. Mark themselves Present during the exact scheduled class interval.
4. Automatically finalize personal attendance as Absent if a valid Present entry was not recorded before the interval ended.
5. Optionally capture a live photo when marking Present.
6. Manually record the status shown by their college ERP.
7. Compare their personal record with their manually recorded ERP record.
8. Review attendance percentages, subject-wise statistics, history, and potential discrepancies.

The application is a personal tracking and record-comparison tool. It is not an official attendance system, does not prove physical presence, and does not determine whether a college ERP record is incorrect.

There are no teacher accounts, teacher approvals, administrative dashboards, or direct college ERP integrations.

# PART 5 — CORE ATTENDANCE BUSINESS RULES

These rules are mandatory and must be implemented in the backend service layer, not just in frontend components.

## 5.1 Personal attendance status

Use an explicit status model for a class session, for example:

- scheduled / upcoming.
- present.
- absent.
- cancelled.

Keep finalization metadata separate from the attendance status when useful.

A session must have a stable unique session ID.

The student's personal attendance and ERP status are separate fields with separate validation rules.

## 5.2 Exact attendance window

Attendance may be marked Present only when:

`scheduledStart <= serverNow < scheduledEnd`

The time must be obtained from the backend's trusted clock.

Reject requests outside this interval, including requests made exactly at the end boundary.

The frontend must not be trusted to provide the authoritative current time.

## 5.3 Automatic finalization

Implement a backend finalization service that identifies eligible sessions whose scheduled end time has passed.

For each session:
- If cancelled, preserve the cancelled state and exclude it from calculations.
- If already finalized, do nothing.
- If a valid Present mark exists, preserve Present and finalize the session.
- Otherwise, set the personal status to Absent and finalize it.

Finalization must be idempotent: running it repeatedly must not change already finalized records.

Use a lightweight recurring background task while the server is running for demo purposes. Also implement server-time checks so late requests are rejected even if the background task has not run.

Do not claim guaranteed background execution after the server stops. Explain this limitation in the project documentation.

## 5.4 Immutability

After finalization:
- The student cannot change the personal status.
- The student cannot change the ERP status.
- The session's finalized attendance data cannot be overwritten by ordinary API requests.
- Attempts to edit finalized records must return a clear validation error.
- Frontend buttons must reflect the locked state, but backend enforcement is mandatory.

The finalizer must never overwrite a valid Present mark received before the deadline.

Do not build a correction or appeal workflow in this MVP.

## 5.5 Class cancellation

Cancelled sessions must:
- Remain identifiable as Cancelled.
- Not count as Present.
- Not count as Absent.
- Be excluded from both attendance denominators.
- Not be finalized as ordinary absence.

## 5.6 Timezone

Use the IANA timezone `Asia/Kolkata` for all student-facing dates and schedule interpretation.

Display timestamps in a consistent format, for example:

`15 Oct 2026, 10:42 AM IST`

Store timestamp instants in a consistent format and convert to IST for display.

Avoid ambiguous date parsing and browser-local timezone dependence.

Ensure weekly recurrence and class-date generation follow the IST calendar.

# PART 6 — ATTENDANCE CALCULATIONS

Implement these calculations in reusable backend functions and expose the results through API responses.

## 6.1 Personal attendance

For all eligible finalized sessions:

Personal Attendance Percentage = Personal Present Sessions / Total Eligible Finalized Sessions × 100.

Present sessions count in the numerator and denominator.

Absent sessions count only in the denominator.

Cancelled, future, and unfinalized sessions are excluded.

## 6.2 ERP attendance

ERP Attendance Percentage = ERP Present Sessions / Sessions with ERP status Present or Absent × 100.

Sessions whose ERP status is null must not count in the ERP denominator.

Show the number of sessions for which ERP status has not been entered.

## 6.3 Theory and Practical

Calculate Theory Attendance and Practical Attendance separately using the same personal attendance formula and the corresponding subject/session categories.

## 6.4 Overall attendance

Calculate overall attendance from aggregate eligible session counts, not by averaging subject percentages or averaging theory and practical percentages.

If the denominator is zero, return a null percentage and display “N/A” or “No finalized classes yet.”

Use consistent rounding, preferably one decimal place in detailed views and whole numbers in compact summary cards.

Keep counts and percentages internally consistent.
